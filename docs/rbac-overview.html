The 30-second version

  • Super Admin can do everything. CEO / CTO / Director see the whole company.
  • Every HR Manager, Manager, Recruiter and Consultant belongs to a group (a pod / team).
  • Group leads (HR Manager & Manager) only see/manage people in their own group.
  • Recruiters work on their own assigned consultants. They can invite Consultants, and only Consultants.
  • Consultants are self-service only — they see their own data and chat with their recruiter + that recruiter's managers.
  • Developer is a scoped admin role with no default access. Each developer gets explicit "capabilities" turned on by a Super Admin.

Groups — the team boundary

A "group" is a pod / mini-team. It's how we keep different recruiting benches from seeing each other.

Who is in a group?
HR Manager(s), Manager(s), Recruiters and Consultants all belong to one group. Admin-tier (Super Admin, CEO, CTO, Director) is global — they aren't tied to any single group.
Why groups matter
A group lead in Cloudfen doesn't see Xeronix's consultants, recruiters or pipeline. Each pod operates in its own lane. Admin-tier sees every pod for org-wide oversight.
The invariant we enforce
When a consultant is assigned to a recruiter, they automatically join that recruiter's group. Move a consultant to a different recruiter (admin only) and the system moves them to the new recruiter's group as well.
No group = no access
A group lead with no group_id is fail-closed: they see no recruiters or consultants until a Super Admin places them in a group. (Org-wide peer chat with other managers still works.)

Important rules we enforce automatically

1. Super Admin is absolute

No other role can move, deactivate, demote or impersonate a Super Admin. A non-Super-Admin can't even invite or grant the Super Admin role to anyone.

2. CEO & Developer mints are Super-Admin only

Only a Super Admin can create another Super Admin or a Developer account. Even the CEO cannot.

3. Last Super Admin protection

The system refuses to deactivate or demote the only remaining active Super Admin — there must always be one. You can't accidentally lock the company out.

4. Rank can never be exceeded

A Director can't promote anyone to CEO. A Manager can't promote anyone to Director. Every role-change check enforces "strictly below your rank."

5. Recruiter invites = Consultant only

A recruiter inviting someone can only invite a Consultant, and only into their own group. The dropdown won't even show the other options.

6. Group leads are always group-scoped

HR Manager & Manager can never accidentally see another group's data — every list, every detail page, every analytics call (including the training assignments, evaluations, supervision notes and compliance report) is filtered by their own group. The only training surface that stays workspace-wide is the shared course catalog itself.

7. Consultants only see their own assignments

A consultant can never see another consultant's resume, applications, interviews or chats. Backend checks every row, not just the page.

8. Hidden = blocked

Hiding a button or a page in the UI is not enough — every protected action is also rejected at the API level. A motivated user with a developer console can't bypass the UI.

Workspace-wide exceptions

A few admin surfaces are deliberately global instead of group-scoped. They are aggregate / org-wide tools, not per-group PII.

Surface Why it's global Who sees it
Reports / Analytics Aggregate org metrics (totals, ratios). Not row-level PII, so group-scoping would just be noise. Admin tier + HR Manager + Manager
Training — course catalog only The catalog (courses, lessons, quizzes) is a shared learning library, not user data. Group leads can browse and assign from it. Assignment-level data (progress, quiz attempts, evaluations, supervision notes, the compliance report) is group-scoped for HR Manager & Manager — they only see learners in their own group. Admin tier sees everything. Admin tier (all) · HR Manager + Manager (catalog workspace-wide, learner data own group only)
User Groups admin Group definitions themselves are org-level. Group leads can't create / pause / delete groups — only admin tier can. Admin tier only
Feature Flags (write) Feature toggles are owner power. CTO / Director can read; only CEO & Super Admin can flip them. Super Admin + CEO

Definition of done — security promises we keep

  1. Every role has a clear allow/deny policy for every page.
  2. Every visible button is also enforced on the server.
  3. Every backend mutation independently verifies who you are.
  4. Every group lead action is scoped to their group, unless it's one of the documented workspace-wide exceptions above.
  5. Super Admin remains absolute, with self-protection + last-Super-Admin protection.
  6. Recruiter can invite Consultants — and only Consultants.
  7. Developer access is capability-only; never accidental business access.
  8. Hidden pages are blocked by the route guard, not just by hiding the link.
