Messaging security & hierarchy — Phase 1Security

In flight · 2026-05-17

Closed three direct-messaging vulnerabilities and centralized the rules that decide who can talk to whom.

Closed

  • Any signed-in user could read another pair's private thread by guessing the URL. Now requires you to be in the same hierarchy or have an existing thread with the peer.
  • Any signed-in user could silently mark a stranger's messages as “read” on their own inbox. Same authorization rule now applies.
  • Any signed-in user could send a message to any other user, bypassing reporting structure. POST /messages now refuses recipients outside your scope.

Behind the scenes

  • New centralized permission service — every check (send, view thread, mark read, future features) reads the same rule set. No more drift between endpoints.
  • Denied requests now write a messages_permission_denied row to the audit log so admins can see attempts.
  • No schema changes, no breaking API changes. Existing conversations stay reachable; only new boundary-crossing attempts are blocked.

Security hardening — round 1Security

2026-05-17

Five high-impact, low-effort fixes from a full-stack audit.

  • Invitation preview email now masked (s************@gmail.com) — blocks email-harvesting via leaked tokens.
  • HSTS bumped to 1 year + includeSubDomains + preload eligibility.
  • Referrer-Policy: strict-origin-when-cross-origin so outbound links don't leak the full URL.
  • Permissions-Policy: camera, microphone, geolocation, payment, USB all denied at the browser level.
  • Per-route rate limit on AI endpoints (30 requests per 5 minutes) — prevents runaway Anthropic spend from a tight loop.
  • Postgres statement timeout (15s default) — prevents a slow query from holding a connection pool slot forever.
  • npm audit wired into CI to catch high/critical CVEs at PR time.

Self-hosted Postgres migrationDev

2026-05-16

Moved off third-party BaaS to a self-hosted Postgres on the same VPS.

  • 40-table consolidated baseline schema. One psql -f init.sql on a fresh DB and the app boots.
  • Production + development databases provisioned separately with isolated credentials.
  • JWT + refresh token auth with bcrypt + session-version revocation.
  • Filesystem storage with HMAC-signed short-lived download URLs.
  • Backwards-compatible data layer — controllers kept their familiar query shape.
